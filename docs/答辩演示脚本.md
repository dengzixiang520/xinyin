# 声见其迹 SONOTRACE · 答辩演示脚本（3 分钟）

> 目标：让评委在 3 分钟内看懂「先质控 → 再可视化 → 后白盒」的闭环，
> 并意识到 **所有数字来自真实训练，不是 PPT 造数**。

---

## 0:00–0:30　痛点与首页（`#dashboard`）

**说**：心音是医生最常用的初筛手段，但它"只能听、看不见、依赖经验、设备之间差异极大"。
我们把它做成可观测、可解释的视觉图谱。

**做**：停在首页，指向顶部三处实时数字：

* 心音记录总数 **11,538** 条
* 累计音频 **75.4 小时**
* 受试者 **5,659** 人 · **7** 个临床库 · **14** 个设备域
* S1/S2 事件级 F1 **0.738**、SQA 5 折 AUC **89.9%**
* 论文实验完成度 **4/12**（右侧"真实训练产物"标签）

**关键一句**：这些数字不是写死的，是后端从论文训练产物里实时读出来的，跑完一个实验它自己会变。

---

## 0:30–1:10　前置质控（`#acquisition`）

**说**：在临床上，录坏了的心音会直接误导诊断。所以我们先质控、再分析。

**做**：
1. 点任意内置样本（如 `13918_AV.wav`），右侧立刻出六维指标：时长 / 能量 / 静音比 / 削波 / 频带信噪比 / 稳定系数
2. 指出 **SQA 随机森林质量概率 85.8%** 与「六维指标全部达标」
3. 拖入一个嘈杂的 wav（或切换 `ZCH0001.wav`），展示问题清单如何逐条给出可操作的整改建议

**关键一句**：这个接口 `/api/quality_check` 就是留给 ESP32 听诊器在采集端做前置拦截的。

---

## 1:10–2:10　声像对照中心（`#visual`）— 演示高潮

**做**：
1. 波形的绿色 `S1` 与红色 `S2` 虚线是 **1D U-Net + Viterbi 生理约束解码**算出来的，不是人工标注
2. 指出右侧「周期 570 ms ≈ 105 BPM」—— 生理上完全合理
3. 点右上「播放」：真实心音回放，橙色指针与波形/谱图同步推进
4. 点击波形任意位置：下方「心音微观观察」放大镜立刻跳转该时段，三图联动
5. 对比 CirCor（异常）与 ZCH（正常）两条样本的 **Log-Mel 与 CWT 双视图差异**

**关键一句**：Log-Mel 看谐波结构，CWT 看瞬态冲击——两个视图互补，这正是我们模型的输入。

---

## 2:10–2:50　白盒分析（`#ai`）

**做**：
1. 大字判定「**疑似异常心音 92.5%**」，下方 11 个 MC-Dropout 采样点全部落在 89–96%
2. 指向不确定度条：**不确定度越高 → 越该交给人复核**（这正是我们做选择性拒识的依据）
3. 开关 Grad-CAM 热力图：高关注区（红）落在收缩期杂音所在的中频段
4. 点「打印 / 导出」，展示白底正式报告单

**关键一句**：我们不给黑箱结论，我们给出**模型在看哪里、有多确信、什么时候该认怂**。

---

## 2:50–3:00　收尾（`#research`）

**做**：切到论文实验看板，指表格。

**说**：这是论文的真实结果面板，Table 1/2/3/4/5 全部与训练产物一一对应；
8 个还没跑完的实验显示 TBD，等服务器跑完自动填上去——**我们从不提前填数字**。

最后指报告单底部声明：本系统仅提供辅助分析参考，**不替代专业医师诊断**。

## 常见追问准备

| 评委可能问 | 回答要点 |
|---|---|
| 模型在哪训练的？ | 云端 3090 单卡，论文流水线 12 个实验 + 1 个分割任务，全部指标可在 `#research` 页核对 |
| 会不会只是这套样本有效？ | 我们做的是**受试者级防泄漏划分**（5 折按患者 ID 隔离），并做了**留一子库 LODO** 与**跨医院零样本**测试 |
| 换一台听诊器还能用吗？ | 这正是核心创新：MixStyle + GRL 域对抗 + 听诊器频响随机化，专门破坏"设备捷径" |
| 为什么不能直接用？ | 明确不替代医师。我们定位是**初筛 + 质控 + 可解释辅助**，最终诊断权在医生 |
| 硬件做到哪一步了？ | 采集端协议已定（单声道 16-bit PCM / 4 kHz / 5–15 s），接口 `/api/quality_check` + `/api/analyze` 已就绪 |
